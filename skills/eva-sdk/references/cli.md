# EVA CLI 与项目凭证文件

只在用户已确认 Demo，或明确要求对目标项目执行本地真实运行时使用本流程。`.env` 由 CLI 写入当前项目目录；agent 只传递它的绝对路径。

## CLI 可用性与登录

1. 在任何全局安装、登录或凭证写入前，确认上游工作流要求的用户 gate 已通过。
2. 运行 `eva whoami`：
   - 命令存在且显示当前登录信息：把它作为已登录证据，继续；只报告必要状态，不复述无关身份信息。
   - `eva` 不存在：展示 owner 确认的安装命令 `npm install -g @autoark-ai/eva-cli@latest`，说明它会修改全局 npm 环境，并等待用户明确确认。确认后执行该命令，再运行 `eva whoami`；不要尝试其他包名、tag 或安装源。
   - 命令表明未登录：告诉用户下一步 `eva login` 会打开浏览器，必须由用户亲自完成登录。
3. 需要登录时运行 `eva login`，保持该操作可供用户完成，并明确等待用户反馈。不得代替用户操作浏览器登录，不得把浏览器打开、命令启动或命令退出视为登录成功。
4. 用户完成后再次运行 `eva whoami`。只有它确认已登录才继续；仍未登录或返回错误时报告 `BLOCKED`，保留原始非敏感错误。

## 在项目目录保存 `.env`

1. 选择目标实际运行的绝对项目目录。运行 Demo 时使用最终快照根下所选 example 的绝对目录；接入项目的本地真实运行使用已声明的目标项目目录。不要使用无关目录，也不要跨项目目录复用 `.env`。
2. 先进入该目录，再运行任何 key 命令：`cd -- <绝对项目目录>`。例如目标目录是 `/private/tmp/cliTest` 时，运行 `cd -- /private/tmp/cliTest`。后续 key 命令必须保持这个 cwd；不要通过其他命令的 `--dir` 选项代替进入目录。
3. 运行 `eva key list`。只用结果判断是否存在可用的 key name；不要把命令包装进 tracing、命令替换或会记录完整输出的脚本。
4. 禁止执行 `eva key show`，也禁止执行任何其他会把 AK 明文打印到 stdout、stderr、终端、日志或工具结果的命令。不要为了诊断、验证 key 或确认 CLI 行为而试运行这类命令；输出一旦产生就会进入 agent 和 LLM 上下文。若某个命令是否会显示 AK 不明确，停止并报告 `BLOCKED`。
5. 如果已有 key：
   - 用户已指定现有 `<key_name>` 时使用该名称。
   - 只有一个可用名称且用户未指定时使用该名称。
   - 有多个可用名称且用户未指定时，只展示 key name 并让用户选择；选择前不要保存或新建 key。
   - 选定后在当前项目目录运行 `eva key save --key-name <key_name>`。
6. 如果没有 key：
   - 生成 `<key_name>`：使用本地时间到秒的 `YYYYMMDDHHmmss`，追加 `_` 和来源 slug。Demo 的 slug 来自 example id；接入项目来自目标目录 basename。把非字母数字连续字符归一为 `_`，转小写并去掉首尾 `_`；结果为空时使用 `eva`。例如 `20260721110300_client_sdk_ts_browser`。
   - 运行 `eva key create <key_name> --no-show-key`。`--no-show-key` 是强制安全选项；任何成功、失败、重试或诊断路径都不得省略，也不得改用会把 key 打印到终端的形式。
   - 创建成功后仍在同一项目目录运行 `eva key save --key-name <key_name>`。
7. save 成功后，凭证文件路径固定为 `<绝对项目目录>/.env`。直接从已知项目目录构造这个绝对路径；不要通过读取、搜索、列目录、检查元数据或调用其他凭证命令确认它。
8. 禁止 agent 读取、显示、复制、解析、搜索、加载、编码、移动、删除或改写 `.env`，也不要把其中的值注入 agent 自己的环境。不要对它使用 `cat`、`sed`、`grep`、`rg`、`head`、`tail`、`jq`、`base64`、`source`、dotenv parser、命令替换、shell tracing、调试日志或等价操作。允许消费方进程在启动后读取该文件。
9. 保存 `.env` 不等于流程完成。调用工作流必须选择消费方文档明确声明的凭证路径启动入口，把该绝对路径作为不可拆分、不可改写的不透明参数值实际传入。不得改用不携带该路径的普通启动入口；消费方没有公开的凭证路径参数时报告 `BLOCKED`，不要自行发明传递方式。
10. 若 key 列出、创建、保存或后续路径传入失败，报告失败阶段、项目目录、key name（如果已确定）和非敏感错误；不要换目录重试，不要执行任何明文查看命令或读取 `.env` 辅助诊断，也不要向用户索要 AK 内容。报告成功时只说明 `.env` 路径已传入，不显示文件内容。
