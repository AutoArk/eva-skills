# 定制 EVA SDK 应用

## 目标

在已验证的 example 或用户项目上修改已发布 SDK 的公开能力与应用层行为，不依赖特定语言、平台或内部实现。

## 执行

1. 明确目标行为、保持不变的行为、完成条件和不可接受失败。定位当前可工作基线；没有基线且改动依赖 runtime 效果时，先执行 `run-demo`。
2. 从目标项目已安装依赖匹配 `sdk-catalog.json`；默认使用当前解析版本的发布物公共契约，不要求先读取或运行 example。只有用户明确选择 Demo 基线时，再读取最新稳定 tag 对应的 example 快照及其版本。
3. 按优先级确认可用公共面：目标项目现有用法、当前版本发布物的 package README、project description、导出声明/类型、相关配置项 JSDoc/源码注释、SDK catalog 官方文档，以及用户明确选择时已解析的 example 快照。涉及模型参数时同时读取 [model-parameters.md](model-parameters.md)，根据 SDK 当前公开能力和限制判断调用组合，再按模型列表核对配套参数；不要要求 SDK 明确列出每个模型，也不要用模型记忆补名称、类型或签名。
4. 先把需求归入职责，不预设某个 SDK 当前一定提供哪些具体选项：
   - 构造与公开配置；
   - 生命周期、控制和资源释放；
   - 输入、输出与可观察状态；
   - 宿主应用的 UI、交互和编排；
   - 发布物明确声明的正式扩展点。
5. 能力可能由 SDK 核心、SDK 的平台适配、浏览器或操作系统，或消费方通过正式扩展点共同提供。必须从所选发布物确认实际责任层；passthrough 只说明该层不重复处理，不能据此断言整体没有该能力，也不能把某个语言的实现方式推导到其它 SDK。
6. 对 VAD、AEC、barge-in、降噪、自动增益、语速、音高、温度等运行时或调优参数，执行 [model-parameters.md](model-parameters.md) 的来源优先级。没有可核验来源时保留 SDK 默认或省略可选字段，不自行发明数值；官方验证起点必须说明代价，并在目标设备和环境中复核。
7. 建立“用户目标 -> 公共契约 -> 目标文件/配置 -> 验证传感器”的映射，再做最小 patch。不要顺带升级 SDK、重构无关模块或更换宿主技术栈。
8. 使用当前生态和平台的原生 checker，按配置/schema、编译或静态检查、lint、针对性测试、release 构建、runtime 的顺序验证。验证粒度要小于改动粒度，并覆盖相关生命周期与资源释放。
9. 回看预期：列出哪些效果已由自动传感器证明、哪些需要用户在真实凭证、网络、权限和目标设备/运行环境中体验。没有真实操作证据时不声明 L3。

## 运行时与声学排障

1. 先区分目标现象，例如无法打断、被自身播放打断、识别漏检或播放异常；静态配置只能形成假设，不能直接宣布根因。
2. 从所选 SDK 的公开事件、状态和配置建立观察路径，按目标环境可用能力核对输入、播放、speech admission、interruption、首次保护窗口与资源生命周期；不得进入 SDK internal 获取额外证据。
3. 涉及音频回声时，先确认回声消除能力实际位于 SDK、平台采集还是消费方扩展层，再比较耳机与扬声器、保护窗口内外、输入输出设备、音量、宿主和平台版本等差异。
4. 只有收集到运行时证据后才调整有来源的参数，并把每次变化、预期、代价与复测结果对应起来。构建通过不能证明声学效果。
5. 优先保留全双工和自然打断。关闭输入、禁用打断或切换半双工等能力降级只能作为最后兜底；执行前必须展示实际证据、说明失去的能力并取得用户明确选择。

## Fail closed

- 发布物公共契约中不存在所需能力：说明缺口，不进入 internal runtime、transport 或测试 seam。
- 用户选择的 Demo 与目标项目 SDK 版本不同：不静默升级/降级；先让用户选择基线。直接定制已有项目时默认保留当前版本。
- 修改需要新的生产凭证分发、后端服务或权限模型：将其作为单独架构决策，不从本地 key-file 流程外推。
- 运行失败且官方 example 也失败：先处理工具链、发布物、Gateway 或目标环境问题，不以大规模应用改写掩盖基线故障。
- 官方资料不足以证明参数兼容性、调优值或根因：保留当前行为并报告证据缺口，不用经验值、跨模型配置或能力降级掩盖不确定性。
