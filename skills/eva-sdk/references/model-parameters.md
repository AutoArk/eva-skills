# 模型参数与能力配置

当用户提到模型、采样率、音色、语言、温度、输出格式、延迟或其他模型相关配置，或 SDK 配置项含义不明确时，必须同时核对两类公开材料：

1. 所选 SDK 发布物本身：package README、project description、导出声明/类型、相关 API 的 JSDoc 或源码注释（只读公开发布物，不进入 SDK internal 实现）。
2. `reference-sources.json` 中 `purpose: model-catalog` 的官方模型列表，当前为 [`gateway-model-list.md`](https://eva.autoarkai.com/api-docs/guide/gateway-model-list.md)。

模型选择必须先查所选 SDK 的公开文档、导出类型和相关注释，确认该 SDK 的公开调用能力、限制条件以及模型字段如何传入；不要要求 SDK 逐一列出模型名称，也不要在 skill 中预设 SDK 支持或不支持哪些模型、上传方式或调用形态。模型列表不能单独证明某种 SDK 调用组合可行。模型列表说明 Gateway/模型能力边界，SDK 文档说明消费方实际可传入的公共配置和限制。只有两者能建立可验证映射的模型与调用参数才可以写入目标项目；不能把模型列表字段自动当成 SDK 参数，也不能凭经验补齐缺失字段。

很多参数与模型是成套变化的。选定或切换模型后，必须回到模型列表核对该模型对应的采样率、音色、语言、格式、延迟、输入输出限制和默认值等配套能力，再回到 SDK 文档确认这些能力是否落在 SDK 的公开配置和调用限制内。不能沿用另一个模型的参数组合，也不能只修改模型名而保留未经核对的参数。

对每个目标参数记录：

- 用户目标和业务场景；
- 模型列表中的能力、限制、默认值和支持范围；
- SDK 对外配置项、类型、默认值、单位和注释；
- 目标项目中的配置位置；
- 配置/schema、类型检查、测试或运行时观察等验证传感器。

外部文档读取遵循 `SKILL.md` 的 Markdown 优先方法。来源不可达、字段冲突或 SDK 没有公开对应配置时，报告 `BLOCKED` 或能力缺口，不修改 SDK 源码，不用模型记忆替代证据。
