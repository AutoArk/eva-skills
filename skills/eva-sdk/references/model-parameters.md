# 模型参数与能力配置

## 参数问答与可行性

当用户提到模型、采样率、音色、语言、温度、输出格式、延迟或其他模型相关配置，或 SDK 配置项含义不明确时，必须同时核对两类公开材料：

1. 所选 SDK 发布物本身：package README、project description、导出声明/类型、相关 API 的 JSDoc 或源码注释（只读公开发布物，不进入 SDK internal 实现）。
2. `reference-sources.json` 中 `purpose: model-catalog` 的官方模型列表，当前为 [`gateway-model-list.md`](https://eva.autoarkai.com/api-docs/guide/gateway-model-list.md)。

模型选择必须先查所选 SDK 的公开文档、导出类型和相关注释，确认该 SDK 的公开调用能力、限制条件以及模型字段如何传入；不要要求 SDK 逐一列出模型名称，也不要在 skill 中预设 SDK 支持或不支持哪些模型、上传方式或调用形态。模型列表不能单独证明某种 SDK 调用组合可行。模型列表说明 Gateway/模型能力边界，SDK 文档说明消费方实际可传入的公共配置和限制。只有两者能建立可验证映射的模型与调用参数才可以写入目标项目；不能把模型列表字段自动当成 SDK 参数，也不能凭经验补齐缺失字段。

很多参数与模型是成套变化的。对 TTS，把 `model + voice + language + sampleRate + responseFormat` 作为同一个兼容配置组；其它能力按官方模型列表声明的依赖关系形成对应配置组。选定或切换组内任一参数后，必须回到模型列表重新核对整个配置组，再回到 SDK 文档确认这些能力落在 SDK 的公开配置和调用限制内。不能沿用另一个模型的音色或参数组合，也不能只修改一个字段而保留未经核对的依赖字段；SDK 类型接受某个字符串不等于 Gateway 支持该组合。

## 离散选项选择

- 用户给出精确 model、voice 或其它离散值时，先验证它属于当前配置组的官方兼容集合；不兼容时报告冲突并停止，不自动切换组内其它参数。
- 用户只要求“换模型”“换音色”或同类修改而没有指定精确值时，从官方模型列表中只提取与当前配置组兼容的候选，展示其公开名称、标识、语言和必要限制并等待用户选择；选择前不得修改目标项目。
- 官方来源不可达、候选不完整或无法建立 model-to-voice 等依赖映射时报告 `BLOCKED`，不得从另一个模型、SDK family、版本或平台借用看似相近的值。
- 用户完成选择后仍要重新验证整个配置组，并使用当前生态的配置/schema、类型检查、构建与必要运行时观察证明修改。

## 配置修改与验证

对每个目标参数记录：

- 用户目标和业务场景；
- 模型列表中的能力、限制、默认值和支持范围；
- SDK 对外配置项、类型、默认值、单位和注释；
- 目标项目中的配置位置；
- 配置/schema、类型检查、测试或运行时观察等验证传感器。

调优参数的取值按以下顺序确定：用户明确指定；当前项目已有且经验证的配置；所选 SDK 正式文档默认值；用户明确选择的官方 example；官方文档声明的验证起点。没有来源的可选参数保持省略，不自行生成数值。文档中的验证起点必须连同适用条件和代价说明，不得改写成通用默认值；编译、类型检查或构建通过不能单独证明运行时、声学或设备效果。

外部文档读取遵循 `SKILL.md` 的 Markdown 优先方法。来源不可达、字段冲突或 SDK 没有公开对应配置时，报告 `BLOCKED` 或能力缺口，不修改 SDK 源码，不用模型记忆替代证据。
