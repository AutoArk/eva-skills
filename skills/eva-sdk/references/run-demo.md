# 运行官方 Demo

## 目标

从 `reference-sources.json` 中唯一的 `purpose: examples-catalog`、`kind: git` source 读取 `repository`、`resolution` 和 catalog path；按该 source 的依赖策略把官方 examples ref 快照拉取到用户指定的明确目录或任务专属临时目录，启动其中一个 Demo，使用该 example 自己的工具链和运行形态自动验证到 L2，并把可操作入口交给用户继续体验。其他用途的 Web source（例如 `purpose: model-catalog`）只用于文档参考，不参与 Demo 快照拉取。

## 执行

1. 执行 `SKILL.md` 的“Demo 依赖解析”，用用户给出的 SDK family、语言、平台、场景或 example id 过滤 catalog；不要选择 catalog 外的组合。
2. 对每个匹配候选只读取 README 首段、manifest/lock 中的版本身份，形成候选卡片：`id`、一句话描述、SDK family、语言、平台、catalog 路径、状态和可确定的 SDK 精确版本。记录解析出的 immutable ref/commit，并检查用户给出的明确目标目录（绝对最终目录）是否不存在或为空；gate 前不读取完整执行文档、原生依赖或平台配置，也不读取目录中的凭证内容。
3. 执行 `SKILL.md` 的“Demo 选择确认”：请求已同时明确精确 example `id` 和绝对最终目录，且两者与当前 immutable ref/commit 匹配、目录不存在或为空时，展示该授权键并直接继续，不做第二次确认。请求存在候选歧义、缺少最终目录、`id` / ref / commit / 目录身份变化，或目录非空时停止并请求对应选择或处置授权，不得继续后续步骤。
4. 用户选择任务临时目录时，保留本任务创建、commit 一致且没有未知新增或修改内容的已验证暂存快照作为最终快照根；该受控快照即使非空也可复用。发现未知内容时，不读取、不清理、不覆盖旧目录，也不接受一句确认把它当成可信快照；提出新的任务专属目录，等待用户选择后在那里重现同一冻结 commit。选择自定义目录时从同一 official repository 取得并 checkout 冻结 commit，并在最终写入前再次核对 commit 与目录为空；不得覆盖非空自定义目录，也不得重新追随 branch tip。所选 Demo 工作目录解析为 `<最终快照根>/<catalog path>`。
5. 在最终快照根运行其自带 catalog validator（若存在），再完整读取所选 example 的执行文档、依赖声明、可复现解析文件、平台配置和公共 SDK 用法。
6. 从 example 材料生成本次执行计划：运行环境、原生依赖恢复方式、静态检查、release 构建、普通启动入口、凭证路径启动入口及其路径参数位置、该凭证入口是否自行执行编译/构建、可观测信号、交互入口和停止/复位方式。Demo 需要 AK 时，文档没有明确凭证路径启动入口就停止；不要把当前 catalog 中某个 example 的命令提升为全局规则。如果 example 同时提供凭证路径启动入口和不带凭证的普通启动入口，默认启动入口立即确定为凭证路径启动入口；不得因为普通入口命令更短、无需 CLI、支持运行时输入 AK，或能够生成不带 AK 的构建产物而自动选择普通入口。只有用户明确要求在运行时手工输入 AK 时，才允许切换到普通启动入口。
7. 授权 gate 满足后、恢复依赖或构建前，先完整读取并执行 [cli.md](cli.md) 的“CLI 可用性与登录”小节。CLI 缺失时按其中的全局安装分支展示唯一安装动作并取得独立许可；浏览器登录仍由用户亲自完成。不要为了预检进入“在项目目录保存 `.env`”小节或提前执行 key list/create/save。
8. 确认本机满足文档声明的 runtime、toolchain、平台与设备要求。使用该生态的 frozen/locked/reproducible 模式恢复依赖；禁止改写解析结果或切换到浮动版本。
9. 先运行当前生态适用的测试、静态检查，以及凭证路径启动入口未覆盖的编译或 release 等价构建。若该凭证入口本身会在启动时执行编译/构建，包括组合完成 build、install、run 的命令，不得在此之前再运行普通 debug 或 release 构建；把该构建推迟到第 12 步，并将 launcher 的构建结果作为本次构建证据。只有凭证入口不包含构建，或用户明确要求额外验证独立 release 产物时，才在本步骤单独构建。保留命令、退出码和必要的非敏感摘要；不要收集可能包含凭证值的 debug output。
10. 所有启动前检查通过后，再执行 [cli.md](cli.md) 的“在项目目录保存 `.env`”小节，把所选 Demo 工作目录作为本次 EVA CLI 项目目录；不要在本文件复制或改写 CLI 的精确命令与顺序。此时才进入 key list/create/save 并保存凭证文件，避免跨越无关阶段悬空保存。
11. 把该 Demo 工作目录下 `.env` 的绝对路径与第 6 步解析出的凭证路径启动入口绑定为本次唯一允许的启动调用。执行前确认调用中包含同一个不透明路径值，且位置和传递形式与 example 文档一致；不要读取或检查路径目标、重写参数名、把内容转成新的配置载体，或生成凭证副本。
12. 按 example 的凭证路径启动入口启动目标，并把第 11 步绑定的不透明路径实际传入；不得改用普通入口、漏传路径或只启动一个未携带凭证路径的进程。若第 9 步已判定该入口自行编译/构建，则该入口此时完成的构建就是本次唯一构建，不再追加普通 debug 或 release 构建。目标可能是持续进程、应用、模拟器、设备任务或一次性程序。需要交互的运行形态保持可用；一次性程序则保留其完成证据，不强行套用常驻服务模型。
13. 选择与目标平台匹配的最便宜可观测信号，例如进程/健康状态、应用 UI、平台日志、设备输出或协议响应。传感器必须同时证明目标来自第 12 步的凭证路径启动调用；其他入口启动的健康进程不能作为 L2。只有传感器确实覆盖了 example 声明的 L2 条件时才判定通过；不要套用其他运行形态的专属信号。
14. 返回 example id、最终快照根、Demo 工作目录、EVA key name、解析出的 tag/commit、SDK 精确版本、实际执行计划、凭证路径已传入的确认（不显示内容）、L0-L2 证据、可操作入口和停止/复位/断开方式。明确邀请用户执行 L3。

## 失败分支

- CLI 缺失、未登录或 key 列出/创建/保存失败：严格执行 [cli.md](cli.md) 的对应分支；保留其中的独立安装确认、浏览器人工参与、登录复查、创建时禁止显示 key 和 `.env` 不透明路径边界，不在这里维护命令副本。不得自动改用不带 AK 的普通启动入口，也不得擅自改为等待用户在设备端手工输入 AK；只有用户明确同意切换后才能使用普通入口。
- 已保存 `.env` 但 example 缺少凭证路径启动入口、启动调用没有携带该文件的绝对路径，或实际运行进程来自其他入口：报告 `BLOCKED`；不要降级为普通启动，也不要把进程存活冒充 L2。
- 自定义最终目录已存在且非空：停止并请求新的空目录；不要合并、覆盖或清空。受控任务暂存快照出现未知内容时同样停止，保留旧目录不动并请求新的任务目录以重现冻结 commit；不得读取未知内容或用一句确认继续污染快照。
- `resolution` 初次指定的 ref 不存在、tag 被移动、冻结 commit 无法取得、本地 snapshot 身份实际变化、catalog 无匹配，或 example 的依赖/运行材料不完整：fail closed，不静默切换到其他 branch、tag 或 prerelease。远端 branch 在 commit 冻结后移动只记录为外部变化；本地 snapshot 身份未变时继续旧 commit，最终自定义目录 checkout 冻结 SHA，不追随新的 branch tip。
- 依赖恢复、静态检查、构建或启动失败：沿 example 声明的工具链与目标平台定位失败层；保留最小复现证据，不修改 SDK 源码来绕过。
- 缺少可验证 L2 的平台传感器：报告已证明的较低层级和缺口，不用其他平台的检查方式替代。

## 停止与清理

给出该运行形态准确的停止、复位或断开方式。除非用户要求，不中止仍供体验的目标，也不删除临时 example；自定义落盘目录永不自动删除。任何时候都不删除或处理 CLI 管理的 AK 文件。
